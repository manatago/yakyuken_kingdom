じゃんけんキングダム：Windows移行指示
更新日：2026-10-16

【このファイルの使い方】
Windowsの今までのゲームディレクトリで作業を続けます。
このファイルはリポジトリのルートにあります。USBでのコピーや新規cloneは不要です。
エージェントには「ルートの Windows移行指示.txt を読んで移行して」と指示してください。

【最新版の取得元】
リポジトリ： https://github.com/manatago/yakyuken_kingdom.git
ブランチ： chore/windows-development-handoff
実装の基準コミット：53931c1073be0fd6a730374a25600868ddfdd14a
このファイルを追加したコミットは基準コミットより後です。
基準コミットへ戻さず、公開ブランチの最新コミットを取得してください。
mainやdevelopへ単にpullするだけでは、この引継ぎ版にはなりません。

【エージェントへの依頼】
MacからWindowsへ開発環境を移します。Mac由来の公開ブランチを正として準備してください。
Windowsの古いリポジトリはほぼ使っていませんが、残存変更を勝手に捨ててはいけません。
重大な問題以外は自律的に進め、ゲーム機能の追加や残タスクの実装は始めません。

【既存ディレクトリを更新する手順】
1. git status --short --branch、git remote -v、git log -1 --onelineで現状を確認。
   本リポジトリであることを確認し、既存のステージ済み／未ステージ／未追跡変更を調べる。
   秘密情報を含むURLやファイル内容をログへ転載しない。
2. 変更の有無にかかわらず、既存ディレクトリ全体を更新前にバックアップする。
   例：janken の隣に janken-backup-YYYYMMDD-HHMMSS を作る。実際の名前は未使用のものを選ぶ。
   バックアップ先は元ディレクトリの外に置き、既存バックアップを上書きしない。
   隠しファイル、.git、未追跡・無視ファイル、ローカル設定も保護する。
   linked worktree等で.gitが外部を参照していれば、単純コピーだけで復元可能と断定しない。
   リンク先を無制限に再帰コピーせず、必要な外部Git管理領域の保護方法を確認する。
   書き込み中のエディタ／Git操作を止め、コピー結果と元のgit statusに対応する内容を確認する。
   バックアップが完了・確認できなければ更新へ進まない。秘密情報はGitへコミットしない。
   大量データ・サブモジュール等で安全な保護ができなければ、その点だけ確認を求める。
   reset --hard、git clean、フォルダ削除、強制checkoutを使わない。
3. Git LFSが利用可能か確認し、git lfs installを実行する。
4. git fetch originを実行する。
5. 引継ぎブランチがローカルに無ければ、次を実行する。
   git switch --track -c chore/windows-development-handoff origin/chore/windows-development-handoff
   ローカルに既にある場合は、履歴と保護状態を確認してから同ブランチへ切り替える。
6. 引継ぎブランチ上で次を実行する。
   git pull --ff-only origin chore/windows-development-handoff
   履歴が分岐していれば自動マージや強制リセットをせず、原因を報告する。
7. git rev-parse HEADで取得SHAを記録し、基準コミットを含むことを確認する。
   保護した古い変更を、新しい版へ自動で戻したりマージしたりしない。
8. AGENTS.md、docs/WINDOWS_HANDOFF.md、docs/ONBOARDING.mdを読む。
   既存ディレクトリの扱いと起動制限については、このファイルを優先する。

【環境準備】
WindowsネイティブのPowerShellを使う。WSLの成功をWindows版成功とは扱わない。
Git、Git LFS、Node.js 22.12.0（CIと同じ）を確認する。
不足ツールに必要な権限は正規に要求し、認証・設定の制限を迂回しない。
次を順に実行し、各終了コードを確認する。

git lfs pull
node .github/scripts/pull-original-assets.mjs --check
npm.cmd ci
npm.cmd run typecheck
npm.cmd run build

失敗したまま成功扱いにしない。LFSポインタのままの画像を描画不具合と誤診しない。
Macのnode_modules、dist、.godotや一時フォルダをコピーしない。
依存の一括更新、npm audit fix、PowerShell実行ポリシーの一律緩和はしない。

【ゲームは勝手に起動しない】
移行準備中はゲーム・エディタを起動しない。
Electronを起動するUIテスト・Smokeテストも今回は実行しない。
詳細資料に起動手順があっても、この制限を優先する。
起動確認はユーザーから別途指示を受けてから。未確認は未確認と記録する。

【認証と保存データ】
GitHub認証とLFSサーバー認証は別。ユーザーは既存LFSのユーザー名／パスワードを所持。
不足時は本人にOSの対話的認証へ入力してもらう。秘密情報をチャット、URL、.env、ログへ残さない。
LFS接続先、HTTP/HTTPS、認証方式、証明書検証、CI設定は変更しない。
通常セーブは変更しない。Macからの実セーブ移行は今回の対象外。
Windows側でコミット・Push・PR作成・main/developへのマージは行わない。

【開発再開時の注意】
Godotだけがセリフ・画像配置・動作の移植原本。独自ストーリーを作らない。
ゲームと開発用エディタは別ビルド。エディタ移植全体はまだ未完了。
残作業は docs/plans/electron-developer-tools-parity.md の1統合タスクを参照。
ギルドからサブイベントへの進行、Skip、Godotバグ修正、身代わりカード報酬、
配布・更新・署名、HTTPS化は保留。移行のついでに変更しない。
編集済みJSONを原本再抽出で上書きしない。
.agents、.agentskillsなどローカル専用ツールの存在を仮定しない。

【完了報告】
既存ディレクトリと全体バックアップの絶対パス、コピー確認結果、変更の有無、ブランチ／SHA、
ツールバージョン、LFS取得結果、型チェック・ビルド結果、未確認事項を報告する。
ゲームは起動していないこと、開発を再開する場所は同じディレクトリであることを明示する。
