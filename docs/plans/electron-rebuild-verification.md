# Matilda縦切りの検証（タスク3.6）

対象：Electron版の現行Matildaチュートリアル。Godot完全再現やゲーム全体の完成判定とは分ける。
基準：[Godot基準シナリオと画像](electron-rebuild-baselines.md)。

## 自動検証

```sh
npm run typecheck
npm test
npm run test:ui
npm run smoke:game
npm run smoke:editor
```

既存のテスト探索機構により、追加テストはWindows/macOSの既存CIにも含まれる。
今回のローカル実行はmacOSのみ。Windowsの結果はPR作成後のCIで確認する。

- 単体：実JSONのアセット参照・遷移検証、全会話の再構築、2回の勝敗、全行程のセーブJSON往復。
  共用チェックの異常系は所持品・所持金・デッキ・保存地点・完了フラグ・台帳の不一致を検出する。
  既存の全手組合せ・グレード比較・80%境界・引分・偽造台帳・保存失敗テストも維持する。
- UI：セーブを事前投入せず「はじめから」から開始。実JSONの全会話を順に表示し、カード追加・削除・自動・準備完了、2回の勝負、締めの会話、終端まで操作する。
  1回目はパーで勝利を確認。2回目のUI結果は乱数に依存するため勝利固定にせず、台帳の件数・確認済み件数を確認する。
  80%境界の決定的検証は単体テストで行う。
- 再起動：グレード説明、デッキ準備、1回目の選択・未確認結果、2回目の選択・未確認結果、完了会話、終端。
  表示内容と保存地点が復元され、ロードだけではセーブのバイト列が変わらないことを確認する。
  各進行段階で所持カード9枚・所持金0を保持し、完了フラグと台帳が一致することを確認する。
- 配置反映：ソース・必要画像を一時プロジェクトへ複製。実エディタでカードボックスのX=1510、拡大率=0.9を保存し、対象ID以外と元バイト列のバックアップを確認する。
  複製プロジェクトのみ再ビルドし、新規開始と再起動後のContinueで同じ配置を確認する。
  元のJSON・実プレイヤーのセーブは変更しない。

## 目視確認の再現手順

`npm run test:ui` は `test-results/matilda/` にFHDのPNGを出力する。
OSのウィンドウ上限とは別にCDPで1920×1080を指定し、画面枠の実測値も検証する。
PNGは無視対象の生成物で、基準画像を上書きしない。

| 画像 | 確認項目 |
| --- | --- |
| introduction.png | 開始会話・背景・立ち絵・Normalの所持カード |
| grades.png | N/B/S/G/P説明、会話の蓄積、手と菱形・N表示 |
| preparation.png | 自動で9枚が表示され、準備完了を操作できる |
| result-1.png / result-2.png | 2枚の大きな勝負カード、勝敗・HP、次の操作 |
| completion.png | 締めの会話と9枚の所持カードを維持 |

チェックリスト：画像欠落がない／手とNが読める／会話と操作ボタンが読める／
パネル・表示領域の切れと重なりを記録する／差を修正済みと誤記しない。
縦横比違いの縮小・余白は既存UIテストで確認する。
動画・HTMLプレイヤー生成器は本プロジェクトにないため、今回の目視素材はPNGのみ。

## Godot版との差分と未解消事項

2026-09-28の目視・コード照合結果。今回は検証追加のみで、差分の修正や新たなデザイン承認は行わない。

| 項目 | 確認結果・扱い |
| --- | --- |
| 初期カード・練習ルール | Normalの各手3枚、9枚の準備、グー固定の1回目、勝率80%の2回目、2回で終了という主要ルールは共通 |
| グレード説明 | 頭文字・同じ手のグレード比較・今回はNormalのみの説明を表示 |
| 開始背景 | Godot保存済み基準画像は街路、Electronは牢屋。Godot章の `get_battle_background()` 自体は牢屋を指定しており、基準画像と章定義が一致していない。撮影経路の再確認が必要。背景を勝手に変更しない |
| 立ち絵・会話領域 | 同じ開始立ち絵を使用するが、ヘッダーが頭部に重なり、会話は中央下の独立パネル。Godotの帯表示・強調演出・追加の表情切替とは一致しない |
| カードパネル | Godotは種類別の枚数表示、Electronは9枚の個別表示。手とNは読めるが、カードボックスとデッキの一部カード名は初期スクロール位置で下端に切れる。スクロール可能でも初期表示の品質課題として残す |
| HPと練習会話 | Godotは上下のHPバー・各段階の会話と強調。Electronは結果パネルのHPと説明に集約し、選択説明・結果別の表情・会話をすべては移植していない |
| アイテム・台座・共通メニュー | Electronのアイテム領域は準備中表示。Godotの木製パネル・台座・Item/Equip/Skip/Save/Load/Config等は再現していない |
| 保存・終了 | Electronは自動保存と単一Continue、締めの後は縦切り終端。GodotのスロットUI・チュートリアル後の本番移行と同一ではない。Godotセーブ移行は既に対象外と決定済み |

この記録は現行縦切りの開始・完了・再開を検証した証拠であり、Godotとの差がすべて承認・解消された証拠ではない。
マイルストーン4へ広げる前に、背景の基準、カード名の切れ、立ち絵の重なり、説明・演出の移植範囲を確認する。
固定バトル・ランダムバトル・ミニゲーム・Godotの実セーブUIの通し検証は今回の対象外。
ピクセル差分の閾値・OS別ゴールデン画像は未導入。カバレッジ率は未測定。

## 固定戦タスク4.2 第3段階（確認用ジン戦）

実行環境：ローカルはmacOS、Electron 44、Node 22。GitHub Actionsのheadless project and item tests、macOS/Windows smoke testsはいずれも成功。

- `npm run typecheck`：成功。
- `npm test`：Unit 69件、Integration 15件が成功。セーブv1の読み込み、ジンの3枚順序付き選択、相手の傾向、引分後の手札再利用、勝利捕獲、敗北時のカード損失と所持金下限、履歴台帳、ベルカ／ジン両順序、0Gでの連続敗北を含む。
- `npm run test:ui`：UI 24件が成功。ジン用3枚選択の保存・再起動、保存失敗後の再試行、対戦結果の再起動復元、カード移動、ギルド復帰を確認。1920×1080、1024×768、600×1000で縦横比と余白を検証。
- `npm run smoke:game` と `npm run smoke:editor`：成功。
- 目視素材：`test-results/jin/battle.png`。1920×1080でカード画像、HP、結果、所持カードの表示を確認。

この段階は確認用ジン戦のみで、マイルストーン4.2全体は未完了。物語への接続と他の3枚戦は別途確認する。
