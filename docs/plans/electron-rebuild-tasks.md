# Electron再構築タスク（統合ロードマップ）

## 運用方針

- 残作業は「Electron版ゲーム本体を通しで完成させる」1タスクとして扱う。A〜Dは内部チェックポイントであり、別タスクには数えない。
- Godotの現在の実行経路を根拠にし、重大な仕様不明以外は暫定判断を記録して作業を進める。
- Electron移行作業ではGodotのコード・シーン・画像を変更しない。
- チュートリアル2種、固定3枚戦、固定1回勝負、ランダム1回勝負、マチルダ本戦の特殊ルールを混同しない。ランダム3回勝負は作らない。
- Windowsを主対象、macOSも対応対象とする。FHD基準で縦横比を維持し、必要な余白を使う。
- JSONを使い、開発エディタは別ビルドとする。Godot版セーブの移行はしない。ミニゲームはゲーム本体に含める。配布・更新・署名は本体完成後に扱う。
- コミット・Pushは明示依頼があるまで行わない。

## 既に用意されている基盤

Electron/React/TypeScript、ゲームと開発エディタの別ビルド、JSONコンテンツとセーブ、コンテンツ検証、単体/UI/CIテスト、タイトル、新規開始、短縮・非性的に再構成したプロローグ、Matildaチュートリアルと通常戦、カード管理、ギルドホーム、装備、冒険者チュートリアル、Stage 1の街とHP1ランダム戦、サブイベント1〜4、Stage 2〜7の物語・固定戦・ミニゲーム。

これらの確認用導線や検証戦は、それ自体では本編完成を意味しない。

## 唯一の残タスク：Electron版ゲーム本体を通しで完成させる

Godot版で現行プレイできるゲーム内容を、Electron版だけでタイトルから現行の最終到達点まで遊べるようにする。物語、固定・ランダム戦、ミニゲーム、会話、勝敗・報酬・敗北先、解放条件、保存・再開を一続きに統合する。

### A. サブイベント1をギルド帰還までつなぐ

- 状態：実装済み。ジン・マルコ・ガルド・ベルカ、ベルカ勝利後の解散・番兵・受付、受付での一度だけの精算、帰還までを実行できる。
- 勝利と敗北、各戦闘・会話地点からの再開、所持金・カード・アイテム報酬の重複防止を実装した。
- ベルカ勝利後のギルド帰還時に `sub1_cleared` を記録し、敗北時は記録しない。
- 継続テストで実装・保存形式・画面遷移を確認する。

### B. ギルドホームから固定戦・ランダム戦と解放条件を使う

- Stage 1の街、6エリアの接続と遭遇率、敵候補と重み、敵の手・グレード、勝利時ドロップ表を現行Godotに合わせる。
- 敵7種の遭遇・勝負開始・勝敗後の台詞を移植し、台詞抽選もセーブ台帳に固定する。立ち絵はGodot側にある未追跡画像変更を取り込まずに接続できる安全な素材源がないため保留。
- ランダム戦はHP各1・3枚デッキで、引分では次のカードへ進む。プレイヤーは所持カードから3枚を選ぶ。ランダム3回勝負は追加しない。
- ランダム戦、Matilda通常戦、ジン／マルコ／ガルド、検証ベルカ、サブイベント1ベルカで、対象のある消耗品を勝負ごとに選択・保存できる。`substitute_card` はカード損失を防止、`iron_shield` はHP損失を防止、`intimidation`／確率調整アイテムは相手の手の抽選を調整し、使用数上限と精算時一度だけの消費を共通処理する。アイテム台帳は任意項目として追加し、過去の途中セーブは未使用の所持品を保持する。Stage 2の再戦へも共通固定戦処理を適用済み。
- 固定1回勝負とランダム戦は独立した遭遇・相手・報酬として扱う。サブイベント1のジン、マルコ、ガルドは固定1回勝負として物語に接続済み。
- 冒険者チュートリアル完了とランダム戦経験をサブイベント1の開始条件にする。後続イベントは直前イベント完了とランダム戦経験を基本にし、Godotの現行条件を確認して接続する。必要回数は設定値として管理する。
- 解放ルールは `content/progression.json` に置く。Godotに全イベント共通の実解放条件がないため、ユーザー指示を反映し、累計ランダム戦3回を暫定設定とする。これは回数の「3」を確定仕様とは扱わず、後で一か所で変更できる。
- サブイベント2〜4とStage 2以降の物語・固定戦・ミニゲームは実装済み。確認用の直接導線と通常進行を共存させる。
- Stage 1相手の立ち絵は現行Git管理対象に安全な素材がないため未接続。機能進行には影響せず、全編照合時に差分として扱う。

### C. 残りの本編・サブイベント・ミニゲームを移す

- Godotの章順に、関連する場面・戦闘・ミニゲーム・報酬・敗北先をまとまりで実装する。章・戦闘・画面ごとに独立完了とは扱わない。
- 固定3枚戦とマチルダ本戦の特殊ルールを個別に再現し、他の固定戦へ誤適用しない。
- 共通ストーリー命令が足りない場合は必要な範囲を追加し、章固有ロジックの乱立を避ける。
- 固定3枚戦とMatilda本戦、HP1のランダム1回戦は別処理として接続済み。ランダム3回勝負は追加しない。
- 既存セーブのカード列・戦闘履歴を後から並べ替え、削除、書き換えしない。

### D. 全編を統合検証して完成を判定する

- 新規開始から現行最終到達点まで、通常進行・勝敗・報酬・途中保存・再起動後の再開を検証する。
- WindowsとmacOSで入力・表示・アセットを確認する。FHDと縦横比の異なる表示を確認する。
- Godot版との相違と意図して移植しない機能を列挙する。
- A〜Dすべてを満たすまではElectron移行完了としない。
