# Electron再構築タスク（ドラフト）

対象計画: [Electron再構築計画](electron-rebuild.md)

## 運用方針

- この文書のチェックは、実装・検証・レビューが完了した時点で付ける。
- Godot版を変更する作業とElectron移行作業は、原則として別PRにする。
- Electron作業は `develop` をベースとする `feature/electron-*` ブランチで進める。
- 「配置を直すためにGDScriptを書き換える」方式をElectron側へ持ち込まない。
- 各マイルストーンの完了後に、次のまとまった実装範囲を確認してから着手する。

## マイルストーン0: 移行の基準を固定する

- [x] 0.1 現行機能の移行台帳を作る
  - 画面、ストーリー命令、バトル、ミニゲーム、開発用編集機能、セーブ項目、アセットを列挙する。
  - 各項目に「初期縦切り」「初回リリース」「後続移行」の優先度を付ける。
  - Godot固有の実装と、移植後も必要なゲーム上の振る舞いを分けて記録する。

- [x] 0.2 基準シナリオを記録する
  - Matildaチュートリアル、固定バトル、ランダムバトル、セーブ・ロードの操作手順と期待結果を記録する。
  - 代表画面のスクリーンショットを基準画像として保存する。
  - 現行版で再現できない既知の不具合は、移植対象の仕様と混同しないよう分けて記録する。

- [ ] 0.3 移行方針の未決定事項を確定する
  - 初回配布の対象OSを決める。
  - 1920×1080基準の固定アートボードと、可変ウィンドウ対応の範囲を決める。
  - コンテンツ形式、開発用エディタの配布形態、旧セーブの移行導線を決める。

**完了条件:** 基準シナリオと優先順位があり、最初の縦切りに含めない機能が明確である。

## マイルストーン1: Electronの最小基盤を作る

- [ ] 1.1 Electron・React・TypeScriptの開発環境を追加する
  - 開発起動、型検査、テスト、パッケージングの入口を整える。
  - 既存Godotプロジェクトとファイル・設定・生成物が衝突しない配置にする。
  - 空のウィンドウを開き、開発時と配布時に同じレンダラーが起動することを確認する。

- [ ] 1.2 メイン・preload・レンダラーの通信境界を実装する
  - context isolation と sandbox を有効にする。
  - ウィンドウ制御、セーブ読込・保存、開発用コンテンツ読込・保存だけを限定APIとして公開する。
  - 任意パス操作や未検証のIPC引数をレンダラーから実行できないようにする。

- [ ] 1.3 テスト実行基盤を追加する
  - 純粋なゲームロジック用の単体テストを実行できるようにする。
  - Electron画面の操作確認を自動化できるUIテスト基盤を追加する。
  - CIへ組み込む前に、ローカルで失敗と成功を確認する。

**完了条件:** 空のElectronアプリが安全な境界で起動し、型検査・単体テスト・UIテストをローカルで実行できる。

## マイルストーン2: データ駆動のゲーム基盤を作る

- [ ] 2.1 カード・グレード・デッキ・勝敗のドメインモデルを実装する
  - グー・チョキ・パーの勝敗と、引分時のグレード比較を副作用なしで判定できるようにする。
  - 所持カード、デッキ制約、報酬など、画面から独立したゲーム状態を定義する。
  - NormalからPlatinumまでの既存カード画像をIDで参照できるカタログを作る。

- [ ] 2.2 セーブ形式と旧セーブ移行器を実装する
  - `save_version` を含むElectron版セーブ形式を定義する。
  - Godot版のJSONセーブを読み取り、検証後に新形式へ変換する。
  - 移行前のファイルをバックアップし、失敗時に既存セーブを壊さないようにする。

- [ ] 2.3 ストーリー・バトル・レイアウトのコンテンツスキーマを実装する
  - 会話、立ち絵、配置、選択肢、画面遷移、バトル開始をID付きの宣言データとして表せるようにする。
  - 相手、デッキ、報酬、特殊ルールをバトルデータとして表せるようにする。
  - ID重複、欠落アセット、壊れた遷移、無効デッキを検出する検証器を作る。

- [ ] 2.4 開発用コンテンツ保存を実装する
  - 変更中の文書、プレビュー、保存済み文書の状態を分離する。
  - 保存時にスキーマを検証し、一時ファイルとバックアップを使って安全に置換する。
  - コンテンツ更新対象をIDで特定し、ソースコードの行番号や正規表現を使わない。

**完了条件:** カード判定とセーブは画面なしでテストでき、ストーリー・バトル・配置データを検証・保存できる。

## マイルストーン3: Matildaチュートリアルの縦切りを完成させる

- [ ] 3.1 タイトルと新規ゲーム開始を実装する
  - 新規ゲーム状態を作成し、Matildaチュートリアルの開始地点へ遷移する。
  - アプリ再起動後に、保存済み状態から適切な画面へ戻れるようにする。

- [ ] 3.2 会話・立ち絵・レイアウト描画を実装する
  - Matildaの会話、グレード説明、背景、立ち絵表示をコンテンツデータから描画する。
  - 1920×1080基準で、会話領域と立ち絵が基準画像に対して妥当な大きさ・位置で表示されるようにする。

- [ ] 3.3 デッキ・手札・カード表示を実装する
  - Normalのグー・チョキ・パーと、`N` グレード表示を再現する。
  - 手元のカードと勝負時のカードで必要な見やすさを維持する。
  - カード画像のアスペクト比・切抜き・拡大方針を共通化する。

- [ ] 3.4 じゃんけんバトル進行を実装する
  - プレイヤーと相手の手を選び、勝敗・引分・グレード比較を反映する。
  - チュートリアルの会話・画面遷移・完了条件をゲーム状態と連携する。
  - バトル途中の保存・再開で、不正な中間状態を作らないようにする。

- [ ] 3.5 開発用レイアウトエディタを縦切りに適用する
  - 立ち絵とカード表示を選択し、位置・拡大率などをプレビューで編集できるようにする。
  - 保存・再読込後に同じIDのレイアウトだけが反映されることを確認する。
  - 通常配布版ではエディタを公開しない。

- [ ] 3.6 Matilda縦切りの自動・手動検証を追加する
  - じゃんけん判定、セーブ移行、コンテンツ検証の単体テストを追加する。
  - 新規開始からチュートリアル完了、保存、再開までをUIテストで確認する。
  - 基準画像との差分と、Godot版との仕様差を確認する。

**完了条件:** MatildaチュートリアルをElectron版だけで開始・完了・保存・再開でき、画面配置をデータ編集だけで修正できる。

## マイルストーン4: 共通画面と主要バトルを広げる

- [ ] 4.1 所持カード・カードボックス・デッキ編集を実装する
  - 所持カード一覧、グレードの視認性、デッキへの追加・削除を実装する。
  - デッキ制約と保存済み状態をドメインモデルで検証する。

- [ ] 4.2 固定バトルをデータから生成する
  - 相手、デッキ、報酬、会話への復帰をバトルデータから生成する。
  - 現行の固定バトルを依存順に移植し、特殊ルールを共通の仕組みとして追加する。

- [ ] 4.3 ランダムバトルをデータから生成する
  - 遭遇候補、相手カード、報酬、出現条件をデータで定義する。
  - グレード分布と報酬調整をコード変更なしで見直せるようにする。

- [ ] 4.4 ストーリー章の共通命令を拡張する
  - 縦切りで不足した会話命令、分岐、演出、遷移を共通コンテンツ機能として追加する。
  - 章ごとの独自コードを増やさず、宣言データで移植できる範囲を広げる。

**完了条件:** 主要なカード管理と固定・ランダムバトルをデータ駆動で実行できる。

## マイルストーン5: 全体移植と切替準備を行う

- [ ] 5.1 残りのストーリー章を移植する
  - 台帳の優先順位に従い、共通命令で表現できる章から移植する。
  - 各章について、遷移・報酬・バトル開始・セーブ地点をコンテンツ検証に通す。

- [ ] 5.2 ミニゲームと補助画面を移植する
  - 初回リリース対象として確定したミニゲームを実装する。
  - それ以外はGodot版に残すか、後続マイルストーンへ明示的に延期する。

- [ ] 5.3 配布・品質保証の仕組みを整える
  - macOSおよび対象に決めたOSでパッケージを作成する。
  - コンテンツ検証、単体テスト、UIテスト、代表画面の画像比較を継続的に実行する。
  - セーブ移行、主要ストーリー、固定バトル、ランダムバトルのリリース判定を行う。

- [ ] 5.4 Electron版を標準版へ切り替える判断を行う
  - 基準シナリオ、未移植機能、既知差分、セーブ移行の結果を一覧化する。
  - 標準版切替後もGodot版をどの期間・目的で保管するか決める。
  - Godot版の削除やアセット整理は、切替判断とは別の承認タスクとして扱う。

**完了条件:** 初回リリース対象の全機能とセーブ移行が検証済みで、Electron版を標準版にする判断材料が揃っている。
